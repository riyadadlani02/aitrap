Read a running AI agent without stopping it.

Debuggers answer questions by freezing the program. That works on a checkout screen. Do it to an agent and the model request times out, the session drops, and the bug you were chasing is gone. aitrap traps capture and continue — real values out of a live process that never pauses.

An agent finds the bug, fixes it, and proves it

What it costs to leave armed

Traps are armed per function, not globally, so code you didn't trap runs at full speed. Measured on Python 3.13.

0.94×untrapped code — indistinguishable from no traps
~18nsadded per call to a trapped function
0times the process pauses

Four commands

No code changes to the thing you're debugging. The launcher puts aitrap on the path; the agent under test never imports it.

Start the process under aitrap

Or set PYTHONPATH for a container you don't launch yourself.

aitrap run -- python my_agent.py

Arm a trap while it runs

A dotted symbol, or a framework hook name so you don't hunt for line numbers.

aitrap trap --trapset livekit --hook on-tool-call

Only capture the case you care about

A predicate over the function's own locals — for the bug that shows up on call 400.

aitrap trap myapp.pricing.apply_discount --when "base_amount < coupon.min_spend"

Read what happened

Returns immediately with a cursor. Nothing blocks, so an AI agent can poll between other work — or open the console in a browser.

aitrap poll 0

Framework hooks

Adapters are plain JSON mapping a hook name to real symbols. Every symbol below was watched firing against a running agent — resolving isn't enough, since a symbol can resolve and never be called, which is how an adapter rots silently when a framework moves a function. scripts/verify_trapset.py reproduces it with no API keys.

Where it stops short

Worth knowing before you point it at anything sensitive.

  • Redaction matches key names, not values. A field called dob is caught; a date of birth buried inside a free-text string is not. Don't assume a captured buffer is safe to paste somewhere.
  • It can't attach to a process that's already running. Entry happens at start-up. Injecting into a live PID needs ptrace or lldb, which is the next thing to fix.
  • Python 3.12 and up. The whole design rests on sys.monitoring, which doesn't exist before that.
  • If you need to step line by line, use a stepping debugger. aitrap deliberately cannot. It does the part they can't.
